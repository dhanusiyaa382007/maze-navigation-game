# 🧭 Maze Navigation Game (Data Structures in C)

A Data Structures project in **C** that generates, solves and lets you play mazes. The C program uses a **stack** and a **linked-list queue** to build mazes and find paths, and a **5-page website** lets you play the same mazes in the browser.

## ✨ Features

- Random **maze generation** using a stack (DFS backtracking), so every maze has exactly one solution and no unreachable cells
- **Shortest-path solver** using BFS with a linked-list queue
- **DFS solver** using a stack, for comparing how many cells each algorithm explores
- **Terminal game** with move counter, timer, undo and hints
- **Website** with 5 pages: Home, Play, Solver, Scores, About
- 5 difficulty levels: Easy (8×8), Medium (12×12), Hard (16×16), Expert (22×22), Master (30×30)
- Animated **algorithm visualizer** showing the queue (BFS) and stack (DFS) in action
- Best scores saved in the browser

## 🧱 Data Structures Used

| Data structure | Implementation | Where it is used |
|---|---|---|
| **Stack** | Array based (`Stack`) | Maze generation (backtracking), DFS solver, rebuilding the shortest path, Undo in the terminal game |
| **Queue** | Linked list (`Queue`, `QNode`) | BFS shortest-path search |
| **2D grid** | 1D array with row-major index `y * w + x` | Storing the maze |
| **Bitmask** | `N=1, E=2, S=4, W=8` | Each cell stores which of its four sides are open |
| **Parent array** | `int par[]` | Tracing the path back from the exit to the start |

## ⚙️ Algorithms and Complexity

| Algorithm | Purpose | Time | Extra space |
|---|---|---|---|
| DFS backtracker (stack) | Generate the maze | O(w·h) | O(w·h) |
| BFS (queue) | Shortest path | O(w·h) | O(w·h) |
| DFS (stack) | Find a path, count explored cells | O(w·h) | O(w·h) |

BFS always finds the **shortest** path. DFS finds *a* path and often explores more cells, which the Solver page and the C program both show.

## 🚀 How to Run

### Requirements
- [VS Code](https://code.visualstudio.com/)
- GCC compiler (MinGW / MSYS2 on Windows). Check with `gcc --version`
- A web browser

### 1. Play in the terminal

```bash
cd c
gcc maze.c -o maze
./maze play 8          # Windows PowerShell: .\maze.exe play 8
```

| Key | Action |
|---|---|
| `w` `a` `s` `d` | Move up / left / down / right |
| `u` | Undo last move (pops the stack) |
| `h` | Hint: shows the shortest path with dots |
| `q` | Quit |

`@` is you and `E` is the exit. The size can be 3 to 40, and an optional seed (`./maze play 8 5`) replays the same maze.

### 2. Print a maze and solver statistics

```bash
./maze ascii 6 4 3
```

Sample output:

```
+--+--+--+--+--+--+
|     |           |
+--+  +  +--+--+  +
|  |     |  |     |
+  +--+--+  +  +--+
|     |     |  |  |
+  +--+  +  +  +  +
|        |        |
+--+--+--+--+--+--+
Shortest path: 12 steps | BFS explored 13 | DFS explored 23
```

### 3. Open the website

Easiest way:

```bash
cd web
start index.html
```

Or in VS Code install **Live Server**, right-click `web/index.html` and choose **Open with Live Server**.

### 4. Regenerate the website levels from C

```bash
cd c
gcc maze.c -o maze
./maze export ../web/levels.js
```

Refresh the browser to see the new data. You can also run the VS Code task **Export levels to website**.

## 🔍 How It Works

1. `c/maze.c` generates each maze by starting at the top-left cell and repeatedly carving into a random unvisited neighbour, pushing cells on a **stack**. When stuck, it pops the stack to backtrack.
2. BFS puts the start cell in a **queue**, visits cells level by level, and records each cell's parent. The path is rebuilt from the exit back to the start using the parent array and a stack.
3. The `export` command writes the 5 mazes and their statistics into `web/levels.js`.
4. The website reads `levels.js` to draw and play the same mazes.
